长期使用主线

这个工具用于长期积累思维认知与科研能力：每天留下预测和结果，把关键证据沉淀到研究地图，每周重组判断，并周期性生成可沟通、可写作、可复现的成果。
核心主线：问题与预期 → 行动 → 结果与证据 → 解释 → 认识变化 → 下一步。
长期科研闭环▼

任务结果沉淀：任务完成后只补最有价值的字段。至少写“实际得到什么”；当结果会改变研究判断时，再补证据、解释、认识变化和下一步。同一任务重复沉淀时会更新已有证据，不重复生成条目。

研究地图：项目地图维护主问题、预期贡献、核心假设、边界、判断和证据；证据可关联到具体核心判断，问题池保存真正会改变判断或行动的未决问题。项目页下方的时间线按时间记录字段快照、判断/证据状态、任务沉淀、问题变化和成果生成。

周复盘：从每日记录中提炼主问题、关键证据、预期变化、重复困惑、技术维护和成果，并明确下周唯一主问题与停止条件。

成果：根据研究地图和已闭环任务生成组会沟通、论文骨架、图表清单、问题清单和复现记录。生成内容是可继续编辑的草稿，可预览并导出。

专注 / 低能量：专注模式隐藏辅助模块但保留核心记录；低能量模式直接定位到一句日志，不修改已有任务和数据。

🧠 思维理念
元原则 —— 科研的底层循环 ▼

先说预期 → 做实验/计算/阅读 → 解释实际与预期的差距

所有框架的底层是这一个循环。不管是 DFT 计算、读文献还是分析数据，这三个步骤反复执行。写下预期，才能知道自己"对"或"错"在哪里。

例：运行 Wien2k SCF 前写"预期自洽收敛在 50 步以内"，实际跑了 120 步——差距迫使你去查参数，而不是被动等待。

升级阶梯详解（6 步） ▼
  1. 把问题写成一句话 —— 问题说不清楚，答案不可能清楚。例："费米面第3条能带在 Γ 点附近断裂，原因未知"
  2. 看极限情况 —— U→0, T→0 有没有解析解，或者最简单结构下会怎样
  3. 找类比 —— 类似体系（如同族化合物）的文献怎么处理这个问题
  4. arXiv / Google Scholar 搜索关键词 —— 先检索，避免重复踩坑
  5. 最小可验证计算 —— 用更小的 k-mesh 或更简单参数快速验证方向
  6. 带着具体问题去问人 —— AI / 同学 / 导师，但需带上前 5 步的结果
规则：不要跳步。不会怎么做 ≠ 可以直接跳到第 6 步去问导师。跳步的代价是问出一个模糊问题，得到一个模糊答案。

清单与预览窗口：小记阅读态和编辑预览都可以直接勾选 - [ ]，勾选后保持当前项目位置；展开小记后的内容置顶、双屏、窗口置顶、阅读/编辑和删除保持在同一操作行，不会拆成两行。点击 ↗ 打开支持最大化、最小化和 Windows 分屏的标准双屏窗口，点击 ▣ 打开始终位于其他窗口上方的置顶预览。编辑区预览栏不再重复显示这两个入口。

☁️ 云端同步说明 ▼

支持 Google Drive 和 GitHub 双端同步，任意一端配置即可跨设备使用（手机看、电脑改）。

Google Drive：点击顶部 按钮，用 Google 账号授权即可。数据存储在 Drive 应用隐藏目录，不占主目录空间。

GitHub：点击顶部 按钮，填写仓库名（用户名/仓库名）和 Personal Access Token（需有 Contents 读写权限）。

同步机制：修改内容 2 秒后自动推送；切回页面、网络恢复或启动读取结束时会补推期间积累的修改；后台每 5 分钟低调检查一次。输入框正在编辑时会延后自动拉取和冲突比较。手动点击醒目的 🔄 或在主页面、双屏、置顶窗口按 Ctrl+S，都会先提交尚在防抖队列里的内容再立即同步。

冲突处理：工具会以最近一次成功同步为共同版本：仅本地修改时自动推送，仅云端修改时自动接收，只有两端都从共同版本继续修改时才提示冲突。首次连接旧版云端文件因没有共同版本，可能保守提示一次。弹窗可选择“合并新增”“使用云端覆盖”或“保留本地并推送”。

数据管理 ▼

业务数据存在浏览器 localStorage，关闭标签页不丢失。“清备份与缓存”只清除本地快照和 PWA Cache Storage，保留日记录、周复盘、小记、设置和云端凭据；“完全清空”会把当前浏览器恢复到首次使用状态。

操作顶部按钮说明
本地备份💾（备份）下载完整 JSON 数据文件，包含所有历史记录、设置、版本号、生成时间和摘要

导出格式说明：

  • 预览：先查看最终卡片、公式和全部区块；窄屏中可在预览区域内滚动
  • PNG：高清图片，匹配当前深浅模式和配色，Markdown 与 LaTeX 按网页内容渲染
  • PDF：使用与 PNG 相同的完整卡片和当前主题，新窗口打开后选择“另存为 PDF”
  • Markdown：今日、历史单日和全部历史会包含完整日记录；研究项目详情包含当前地图、关联任务结果和完整演化时间线；月任务和全部历史等纯文本目标不生成图片
  • JSON：完整数据备份，用于导入恢复

统计导出：沿用统计页当前项目筛选，包含总览、科研成果转化、项目活跃、连续记录、类型趋势、活跃热力图及全部图表和图例。

随手小记导出：选择“全部随手小记”时会弹出选择框，可勾选条目；不选择时导出全部，不再只截取最近部分。

最佳实践：配置 GitHub 或 Drive 同步，数据自动备份到云端；重大编辑和云端恢复前会保留最近 5 次本地快照，同时定期用 💾 导出 JSON 作为离线备份。

恢复向导与冲突处理 ▼

导入恢复：导入 JSON 后先进入恢复向导，可按日期、周计划、小记和设置选择范围。日期支持全选、清空、反选、仅新增和跳过覆盖；部分导入会以合并方式写入，避免删除未选择内容。

冲突详情：同一天两端都修改时会保留本地，并显示字段级差异。可逐字段应用云端、批量使用云端、仅补云端新增字段或全部忽略；批量操作的二次确认会直接显示在当前详情之上。

科研建议：不确定时先导出完整 JSON，再做恢复或批量冲突处理。数据本身就是研究记录的一部分，保留可追溯性比追求一次性整理干净更重要。

故障排查 ▼
现象处理方式
同步失败打开“同步详情 / 自检”，查看 Drive 或 GitHub 最近状态；GitHub 常见原因是 Token 失效或仓库权限不足。
多端数据不一致出现冲突弹窗时先看本地/云端摘要；一般优先选“合并新增”，不确定时选择“稍后处理”，再导出 JSON 备份。
冲突详情看不懂冲突详情会尽量显示页面上的名称，例如“晨间任务”“研究伙伴状态”“价值评估”；如果仍出现内部字段名，可导出冲突报告后再手动比对 JSON。
导入后担心覆盖错导入前会自动生成快照；可在“最近本地快照”中全部恢复，或只恢复某一天。
打卡没有续接检查上一天任务是否选择“当日完成”；如果是在历史编辑里补改昨天，保存后会自动补续接到今天。
删除历史任务后续未完成变化选择“仅删除这一天”时，若其他日期仍有同链未完成，拖延天数会从剩余最早日期重新计算；选择“不再继续”时会隐藏这条续接候选，但不删除其他历史日记录。
导出图片不对先点“预览”确认公式、主题和全部区块；统计导出沿用当前项目筛选，历史单日导出需要先在历史页打开某天详情。
